# ML-модули «Инспектор ИИ»

Python-часть архитектуры ТЗ 1.5: разбор документов и проверка комплекта по
матрице. С сервером (Node.js, `packages/server`) связана очередью RabbitMQ и
внутренним REST; собственной базы данных нет — матрицу, правила и процессы
передаёт сервер, оригиналы файлов хранит сервер в зашифрованном виде.

| Процесс | Что делает |
|---|---|
| `python -m app.worker` | слушает `inspector.parse` и `inspector.inspect`, отвечает в `inspector.results`, ход проверки — в `inspector.progress` |
| `uvicorn app.service:app` | внутренний REST: `/render`, `/llm-check`, `/evaluate`, `/rules/validate`, `/health`, `/metrics` (только со служебным токеном) |

Модули:

- `documents.py`, `local_ocr.py`, `classification.py` — страницы, OCR (Tesseract), раздел тома;
- `cv.py` — CV-анализ чертежей: масштаб по размерным линиям, линии, измерения (ТЗ 9.1, п.3);
- `cad.py` — DWG/DXF: сервер при приёме приводит чертёж к DXF, здесь он отрисовывается в PDF с текстовым слоем, размеры сверяются с геометрией;
- `semantic.py` — семантические якоря Sentence-BERT в ONNX (ТЗ 9.1, п.2);
- `official_pipeline.py` — выбор редакций и сверка по матрице с доказательствами;
- `suspicions.py` — свободный поиск гипотез (ТЗ 9.5);
- `evaluation.py` — метрики по эталону (ТЗ 14);
- `kv.py`, `facts_store.py` — кэш разбора по SHA-256 в Redis, зашифрованный AES-256-GCM;
- `sources.py` — получение файла с сервера и приведение к PDF на время задачи.

Переменные окружения — `docs/ЗАПУСК.md`. Тесты: `make test`.
