# Структура программы и последовательность действий

Прослежено по коду: шаги ниже идут в том порядке, в каком выполняются.

## 1. Главная идея

Проверка идёт **по Матрице контроля** (132 параметра, таблица `params`).
Каждый параметр — вопрос «совпадает ли значение в ПД, РД и ИД». Модель
отвечает значениями с цитатами; код проверяет, что цитата реально стоит на
указанном листе, и сам строит координаты. Всё, что проверить не удалось,
остаётся видимым состоянием (`MISSING_EVIDENCE`, `CLARIFICATION_REQUIRED`,
`technical_status: not_run`, процесс `ERROR`), а не «нарушений нет».

## 2. Три процесса и связь между ними

| Процесс | Язык | Что делает |
|---|---|---|
| сервер (`packages/server`) | Node.js | принимает файлы, хранит всё, ведёт процессы, протоколы, решения, аудит, выгрузки, РиН |
| ML-воркер (`packages/ml/app/worker.py`) | Python | берёт задачи из RabbitMQ: разбор файла и проверку комплекта |
| ML-API (`packages/ml/app/service.py`) | Python | отвечает серверу сразу: изображение листа, связь с моделью, метрики, синтаксис правила |

У ML-модулей нет своей базы: файлы они берут у сервера по внутреннему REST
(`/internal/files/<sha256>`, служебный токен) на время задачи, матрицу,
правила и прошлый протокол получают в самой задаче. Разбор документа
хранится в Redis по SHA-256 — зашифрованным.

## 3. Путь документа

```text
POST /api/v1/documents/upload                                   сервер
  ├─ антивирус ClamAV до сохранения                             domain/antivirus.ts
  ├─ тип по содержимому, лимиты, PDF / DOCX / XML / DWG / DXF    domain/formats.ts
  │    DWG/DXF → DXF AC1032 UTF-8 (производный файл)            domain/cad.ts
  ├─ реестр: JSON / CSV / XLSX, SHA-256, связь редакций          domain/registry.ts, intake.ts
  ├─ хранилище AES-256-GCM по отпечатку                         storage/fileStore.ts
  └─ задача «разобрать файл» → inspector.parse                  domain/pipeline.ts

ML-воркер: parse                                                 worker.parse
  ├─ файл с сервера; DOCX/XML → PDF; DXF → PDF с текстовым слоем sources.py, document_convert.py, cad.py
  ├─ текст страниц, OCR сканов (качество OK/LOW_QUALITY/ABSTAIN) documents.py, local_ocr.py
  ├─ CV чертежей: масштаб, линии, расхождение размеров          cv.py
  ├─ раздел тома                                                classification.py
  └─ результат → inspector.results; разбор — в Redis            facts_store.py, kv.py
```

## 4. Процесс проверки

```text
все файлы процесса разобраны → задача inspector.inspect           pipeline.dispatchIfReady
ML-воркер: inspect                                                  worker.inspect
  ├─ дозагрузка не изменила актуальные редакции → прежний протокол  worker.reuse_previous
  ├─ связь с моделью; нет связи → ошибка задачи (повтор, ERROR)
  ├─ актуальная редакция по каждому шифру                           official_pipeline.select_current_documents
  ├─ страницы под параметр: шаблон, смысл (Sentence-BERT), слова    official_pipeline._relevant_facts, semantic.py
  ├─ сверка пачками параметров, проверка цитат и bbox               official_pipeline.run_official_analysis
  ├─ графическая сверка листов                                      lean_analysis_runtime.py, vision.py
  ├─ инкрементально: только параметры с новыми данными              worker.affected_codes, merge_incremental
  ├─ свободный поиск: логика, семантика, нормы, ML-паттерн          suspicions.py
  └─ ход → inspector.progress; остановка — флаг в Redis
сервер: результат → процесс, версия протокола, Checks,              pipeline.applyInspection
        Evidence_Fragments, Suspicions; уведомление инспектору
```

## 5. После проверки

```text
решения инспектора (версия, кодированная причина)   processes.decide
гипотезы: в кандидаты — только с координатами       processes.reviewSuspicion
«Завершить» — когда все кандидаты решены             processes.finalize
выгрузка JSON / XML / DOCX / PDF / CSV               domain/export.ts
передача в ИАИС «РиН», повторы 1 / 5 / 15 мин        domain/rin.ts
GOLD-набор, выпуски, приёмка моделей, отчёт          domain/feedback.ts, routes/ml.ts
```

## 6. Фоновые задачи сервера (`jobs.ts`)

Сроки задач очереди (повтор, затем `ERROR` и уведомление), повторы передачи
в РиН, еженедельный отчёт по дообучению, проверка целостности хранилища,
резервные копии (каждые 15 минут и ежедневно), снимок метрик, очистка
истёкших сессий.
