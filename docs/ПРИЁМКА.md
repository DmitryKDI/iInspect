# Приёмка качества на стенде (ТЗ 14; лист «Метрики» матрицы)

Метрики считаются на стенде с GPU по эталонной разметке заказчика. Эталон и
документы объектов в репозиторий не кладутся: храните их вне каталога проекта.

## 1. Подготовить эталон

Эталон — JSON в полях листа «Схема GOLD» (по записи на evidence_group):

```json
{
  "groups": [
    {
      "evidence_group_id": "EG-…", "object_id": "…", "matrix_code": "M-078",
      "finding_status": "CONFIRMED_VIOLATION",
      "source_expected_file_id": "…", "source_expected_page": 26,
      "source_expected_bbox_polygon": [[0.10, 0.20, 0.35, 0.40]],
      "source_expected_code": "…", "source_expected_revision": "…",
      "source_actual_file_id": "…", "source_actual_page": 3,
      "source_actual_bbox_polygon": [[0.40, 0.10, 0.70, 0.30]],
      "source_actual_code": "…", "source_actual_revision": "…"
    }
  ],
  "ocr":        [{"file_id": "…", "page": 1, "text": "эталонный текст страницы"}],
  "key_fields": [{"file_id": "…", "field": "code", "value": "…"}]
}
```

`finding_status` — `CONFIRMED_VIOLATION` (положительная группа) или
`NEGATIVE_VERIFIED` (проверенная отрицательная). `file_id` — те же
идентификаторы, что в реестре файлов при загрузке. bbox — доли видимого листа
[0;1] с учётом CropBox и поворота. Выгрузка выпуска набора
(`GET /api/v1/ml/dataset/versions/{v}/export`) имеет тот же формат и годится
как эталон для следующей модели.

Графические нарушения, не привязанные к параметру матрицы, записываются с
пустым `matrix_code`; для них засчитывается графический кандидат с верными
листами и рамками.

## 2. Прогнать объекты

```bash
docker compose up -d
# вход: токен из поля token
curl -s -X POST https://стенд:5443/api/v1/auth/login -H 'content-type: application/json' \
  -d '{"login":"…","password":"…"}'
# загрузка комплекта с реестром (JSON/CSV/XLSX) → process_id
curl -H "authorization: Bearer $TOKEN" -F files=@… -F registry=@реестр.xlsx \
  https://стенд:5443/api/v1/documents/upload
# дождаться статуса READY или COMPLETED
curl -H "authorization: Bearer $TOKEN" https://стенд:5443/api/v1/processes/<id>/status
```

## 3. Посчитать метрики

`POST /api/v1/ml/evaluate` с телом `{"reference": …, "process_ids": […]}`
(роль ML-инженера). Сервер передаёт процессы и матрицу ML-модулям, эталон
не сохраняется и не пишется в журнал. Ответ — отчёт с полем `passed`.

| Метрика | Как считается | Порог |
|---|---|---|
| `character_accuracy` | 1 − ΣLevenshtein / Σсимволов после NFC и схлопывания пробелов; отдельно CER, WER, coverage | ≥ 0,95 |
| `key_fields_exact_match` | точное совпадение шифра, стадии, редакции, раздела, диапазона листов; поле, которое сервис не извлекает, — промах | ≥ 0,90 |
| `document_linkage` | выбранная актуальная редакция совпадает с шифром и редакцией источников эталона | ≥ 0,95 |
| `localization` | файл и страница совпадают, IoU ≥ 0,50 с рамкой эталона — для обеих стадий | ≥ 0,95 |
| `precision` / `recall` / `f1` | по evidence_group: верный параметр и верное доказательство | ≥ 0,90 / 0,80 / 0,85 |
| `false_positive_rate` | FP / (FP + TN) на `NEGATIVE_VERIFIED` | ≤ 0,10 |

К каждой метрике — размер выборки и 95%-й доверительный интервал (Уилсона;
для F1 — бутстреп). Отдельно — разбивка по разделам и по параметрам, доля
отказов от ответа (`abstention_rate`). Метрика без данных — «не посчитано» и
не считается пройденной.

## 4. Что проверять на эталонных графических нарушениях

Нарушения, видимые только на чертеже (изменённая конфигурация оборудования в
помещении, отсутствующие на плане РД контуры или ответвления систем), в
текстовой сверке по матрице не видны. Их находит графическая сверка листов.
На стенде проверить: пара листов ПД/РД подобрана, кандидат выдан с листами
обеих стадий и рамкой в зоне помещения, `localization` по этим группам ≥ 0,95.
